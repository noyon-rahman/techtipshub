# Taste — Command Code
- When debugging platform/infrastructure errors, expects genuine research (official docs, upstream source, issue trackers) rather than guesswork — and asks for it explicitly ("do some real research"). Cite the sources used. Confidence: 0.75
- Wants a root-cause diagnosis plus concrete evidence that the fix works (typecheck/lint/format/build run), not just a patch. Confidence: 0.6
- Judges infrastructure work against "prod grade standards": mail must be reachable (a real reply-to mailbox, never a dead no-reply), with retries/timeouts/idempotency and both text and HTML bodies — not just a send call that happens to return 200. Confidence: 0.7
- "Implement it properly" means the whole surface moves together — config schema, `.env` files, dependency list, docs, and verification — not a minimal patch at the call site. Confidence: 0.6
- Works in pnpm + Turborepo monorepos with `apps/` and `packages/` layout, TypeScript throughout; deploys to Vercel. Confidence: 0.6
- Sends transactional email through Resend (API key + verified custom domain via env vars) rather than Nodemailer/Gmail SMTP; dropping the old SMTP stack entirely is expected. Confidence: 0.7
- Wants sending identities modeled as multiple addresses on one verified domain (e.g. security@, support@, notifications@), chosen per flow, so new senders don't need a new config variable. Confidence: 0.65
- Uses Hono as the API framework on Node (`@hono/node-server`), with separate entrypoints for the long-running dev server vs. the serverless handler. Confidence: 0.5
- Prefers a production-grade, widely adopted library over hand-rolled markup/plumbing ("use a prod grad library") — e.g. MJML for email templates instead of hand-written HTML tables. Confidence: 0.7
- Generated UI (including email) must follow the brand: the project's DESIGN.md color tokens, accents, and typefaces rather than generic system styling. Confidence: 0.7
- Treats responsiveness on every device/screen width as a baseline requirement, not a nice-to-have. Confidence: 0.7
- Explicitly asks for speed via fan-out: multi-part or multi-surface tasks ("do all the tasks faster run multiple agents") should be split across several parallel subagents with disjoint file ownership, not done serially. Confidence: 0.85
- Runs the antislop skill in "during" mode as a standing global preference, so writing/UI rules (no em dashes, sentence case, no marketing tone, contrast/focus/mobile checks) apply while code is written, not as a later cleanup pass. Confidence: 0.7
- House code-comment style: comments stay short and why-focused (max two lines); never add comments that narrate what the code already says. Confidence: 0.6
- Before declaring work done, expects the full local verification chain run per app — typecheck, lint without autofix, and a production build — and honest reporting of anything not verified (e.g. no live click-through). Confidence: 0.65
- Passing typecheck/lint/build is not accepted as proof a feature works: reports non-working interactions bluntly ("nothing happens, fix it") and expects the interaction actually exercised, with the root cause found. Confidence: 0.5
- Admin capabilities belong inside the admin section: admin edit/management UI should live on its own `/admin/...` routes under the admin layout (sidebar, topbar, breadcrumb), not be bolted on as an "admin mode" of a member-facing page. Confidence: 0.75
- Expects admins to have full authority over user content — edit any article (including fields like its slug/address) and any user's profile from admin screens — rather than users' rights capping what an admin can fix. Confidence: 0.65
- Destructive actions must be gated behind an explicit confirmation modal that names the item, states the consequences, and warns it cannot be undone; irreversible delete is a deliberate second step available only for already-trashed items, never a direct replacement for soft delete. Confidence: 0.6
- Prefers admin management screens grouped as tabs on one page (e.g. Published/Deleted articles; Articles/Members trash) with soft-delete + restore, instead of separate pages reached by redirects. Confidence: 0.65
